How should users specify time?

Default is "now". How do we express other times?

The scenarios

NOW (default)
"What's next?" — standing at the station
LATER TODAY
"What's available around 14:30?"
SPECIFIC DATE
"What runs on Tuesday?"
DATE + TIME
"Tuesday around 9am"
A

Flags Only

Explicit --at and --on flags

tt home work                          # now
tt home work --at 14:30               # today at 14:30
tt home work --on tuesday             # next Tuesday, now-ish
tt home work --on 2026-03-17          # specific date
tt home work --on tuesday --at 9:00   # Tuesday at 9am
tt home work --on tomorrow            # natural day words

Pros

  • Unambiguous — no parsing guesswork
  • Composable — --on and --at work independently
  • Tab-completable

Cons

  • Verbose for quick queries
  • "--at 14:30 --on tuesday" is a lot of typing
B

Positional "at" keyword

Natural English-like syntax with "at" as separator

tt home work                          # now
tt home work at 14:30                 # today at 14:30
tt home work at 9:00 on tuesday       # Tuesday at 9am
tt home work on tomorrow              # tomorrow, now-ish
tt home work on 2026-03-17            # specific date

Pros

  • Reads like English
  • Quick to type
  • Memorable

Cons

  • "at" could clash with station names
  • Positional parsing is fragile
  • Unconventional for CLI tools
C

Smart Positional Argument

Time/date as optional last argument — auto-detected by format

tt home work                          # now
tt home work 14:30                    # today at 14:30
tt home work tomorrow                 # tomorrow, now-ish
tt home work tuesday                  # next Tuesday
tt home work "tuesday 9:00"           # Tuesday at 9am
tt home work 2026-03-17               # specific date

Pros

  • Shortest possible input
  • Feels natural
  • Works like "remind me tuesday" style tools

Cons

  • Ambiguity risk (is "bath" a station or...?)
  • Quoting needed for date+time combo
  • Harder to implement reliably
D

Hybrid: Flag for date, positional for time

Time is common enough to earn a shortcut. Date is rarer, gets a flag.

tt home work                          # now
tt home work 14:30                    # today at 14:30
tt home work 9:00 --on tuesday        # Tuesday at 9am
tt home work --on tomorrow            # tomorrow, now-ish
tt home work --on 2026-03-17          # specific date
tt home work 14:30 --on 2026-03-17    # date + time

Time is always HH:MM format (colon required) — no ambiguity with station names. Date uses --on flag so it's explicit.

Pros

  • Common case (time today) is short
  • No ambiguity — colon means time, --on means date
  • Conventional flag for the less-common option

Cons

  • Mixed positional + flag style
  • Must remember which is which
