Independent Analysis: What Did 3 Agents Find?

Comparing independently-derived answer taxonomies

Convergence: All 3 agents agreed on these

Departure Board
List of services leaving a station. The "what's running?" question. Can be filtered to a destination or not.
= our A→... and A→B list
Arrival Board
What's coming in? "When does Dad's train arrive?" "Which platform?"
= our ...→B
Service Detail / Calling Pattern
Full route of one train. Every stop with times, platforms, progress. "Where is it now?"
= our Journey
Quick Status
Single-fact answers: "Platform 6", "12 min late", "Cancelled — signal failure". Often a follow-up.
= our Status

New ideas the agents surfaced

Next Train (single best answer)
Not a list — THE answer. "Next train home is 18:42, platform 3, on time." The most common real-world question deserves a first-class command.
We had this in command proposals but not as a distinct answer type
Cancellation + Alternatives
"My train's cancelled — what do I do?" Answer isn't just "cancelled" but includes the next viable option. Requires combining cancel info with remaining services.
Agent 1 flagged this as a distinct need
Live Progress Tracking
"Where is it right now?" Not just the calling pattern, but highlighting current position: APPROACHING, AT_PLAT, DEP_READY. Parent tracking a kid's journey.
Service detail data supports this via serviceLocation field
Confidence Layer
Agent 3 highlighted: "how reliable is this info?" — realtimeActivated, platformConfirmed, *Actual vs estimated. Not an answer type itself but a quality dimension on every answer.
Cross-cutting concern, not a separate command

Explicitly ruled out (API can't support)

Multi-leg Journey Planning
"How do I get from A to B with a change at C?" — API only does single legs. Would need orchestration across many calls. All 3 agents flagged this as out of scope.
Ticketing / Pricing
No fare data in the API at all.

Debatable: Our "Overview/Aggregate" type

We had "Overview (Aggregate)" — average lateness, cancellation rate. Agent 1 included it but noted it needs aggregation across many queries. Agent 2 called it "historical/analytical" and noted it's a developer/power-user need. Agent 3 didn't surface it at all.

Verdict: Possible but expensive (many API calls). Could be a v2 feature. Not core to "world class usability" for the common case.

Revised Taxonomy

Answer Type Shape Human question Priority
Next Train Single service "When's my next train home?" ⭐
Board Service list (deps or arrivals, optionally filtered) "What's leaving?" / "What's arriving?" ⭐
Service Calling pattern with live progress "Show me the full route" / "Where is it?" ⭐
Status Single fact (platform, delay, cancelled) "Is it on time?" / "What platform?" v1
Overview Aggregate stats across services "How's it running today?" v2
Cross-cutting: Confidence indicators (realtime activated, platform confirmed, actual vs estimated) should be woven into all output, not a separate command.
