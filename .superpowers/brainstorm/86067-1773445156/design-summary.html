Design So Far

Command Structure

Core commands
tt home work                          # next 3 trains (default cmd = next)
tt next home work                     # same thing, explicit
tt board home                         # full departure board
tt board home --to work               # board filtered to destination
tt board home --arrivals              # arrival board
tt service G54821                     # full calling pattern (today)
tt service G54821 --on 2026-03-17     # calling pattern on specific date

Time & date (flags, conventional style)
tt home work --at 14:30               # today at 14:30
tt home work --on tomorrow            # tomorrow
tt home work --on tuesday             # next Tuesday
tt home work --on 2026-03-17          # specific date
tt home work -t 9:00 -d tuesday       # short flags

Aliases
tt alias set home HIB                 # save alias
tt alias set work MOG                 # save alias
tt alias list                         # show all aliases
tt alias remove home                  # delete alias

API base layer (kept out of the way)
tt search HIB                         # raw location search
tt search HIB --to MOG --on 2026-03-17 --at 1430 --arrivals
tt service G54821 --on 2026-03-17     # (shared with core)

Output control
tt home work --json                   # JSON output for scripting

Answer Types → Commands

Answer type Command Output
Next train tt [from] [to] 1-3 services, compact, countdown
Board tt board [station] Table of services, departure board style
Service tt service [uid] Full calling pattern, live progress
Search (API) tt search [station] Raw-ish output, power users

Key Decisions

✓ Typer + Rich
CLI framework + beautiful output
✓ Fuzzy station names + CRS codes
Both accepted, short = code, long = search
✓ Station aliases
tt alias set home HIB
✓ Non-interactive
Pure CLI, scriptable, pipeable
✓ Drill-down via UID
Board shows UIDs, tt service drills in
✓ Conventional flags
--at, --on, --arrivals, --json
